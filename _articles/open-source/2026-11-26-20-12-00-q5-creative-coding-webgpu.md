יש משהו מעט פרדוקסלי ברעיון שמאחורי q5.js: כדי להפוך יצירה גרפית באמצעות קוד לנגישה יותר, היא נשענת דווקא על חומרה מתקדמת. במקום לדרוש ממתחילים ללמוד תחילה את הפרטים של ממשקי GPU, הספרייה מציעה להם כמה פקודות ציור פשוטות — עיגול, קו, צבע ואנימציה — ומעבירה את העבודה הכבדה אל כרטיס המסך.

q5.js היא ספריית JavaScript ליצירה חישובית (Creative Coding): תחום שבו קוד משמש לא רק לבניית תוכנה, אלא גם ליצירת תמונות, תנועה, דפוסים, צעצועים אינטראקטיביים ואמנות גנרטיבית. היא שואבת השראה מהמסורת של Processing ומספריית [p5.js](https://p5js.org/), אך פונה לכיוון משלה: מנוע גרפי שמכוון במיוחד ל-WebGPU, תמיכה ב-Python וניסיון לשמור על כניסה פשוטה לעולם הזה.

המאגר [q5js/q5.js ב-GitHub](https://github.com/q5js/q5.js) ציבורי ופעיל, והספרייה מופצת תחת רישיון LGPL-3.0-only. בקובץ package.json שנבדק ב-26 בנובמבר 2026 מופיעה גרסה 4.10.1. q5.js אינה מנסה להיות מנוע משחקים מקיף. היא מתמקדת במשימה מצומצמת יותר: להפוך ציור אינטראקטיבי בדפדפן למהיר ונגיש, גם במחיר של פשרות הנדסיות מוגדרות.

## מהי יצירה חישובית, ולמה צריך בשבילה ספרייה?

ביצירה חישובית כותבים תוכנית שמתארת תהליך חזותי. במקום למקם כל נקודה וצורה באופן ידני, אפשר להגדיר כלל שמפזר אלפי צורות לפי נוסחה, מגיב לתנועת העכבר, משנה צבע בהתאם לצליל או מייצר קומפוזיציה חדשה בכל טעינה.

המודל של p5.js ממחיש היטב את הגישה הזאת. פונקציית setup מכינה את סביבת הציור, ופונקציית draw רצה שוב ושוב — בדרך כלל 60 פעמים בשנייה. בכל מחזור אפשר לקרוא את מיקום העכבר, לחשב ערכים חדשים ולצייר את הפריים הבא. כך ציור סטטי יכול להפוך בהדרגה למערכת שמגיבה לקלט ומשתנה בזמן אמת.

ספריות מהסוג הזה חוסכות מהיוצר חלק גדול מהעבודה הטכנית. אין צורך להתחיל מהגדרה של משולשים, ניהול זיכרון גרפי או כתיבת shaders. אפשר לעבוד במונחים מוכרים יותר של צורות, צבעים ותנועה. זו אחת הסיבות ש-p5.js נעשתה כלי מוכר בהוראה וביצירה: היא מחברת בין תכנות לשפה חזותית שקל להתנסות בה.

q5.js פועלת באותו מרחב, ומציגה את עצמה כחלופה קלה ומהירה יותר, המותאמת במיוחד לאמנות אינטראקטיבית. היא אינה קשורה רשמית ל-Processing Foundation או לפרויקט p5.js. ה-README שלה מתאר את מקורות ההשראה ואת התאימות, לצד פירוט של רכיבים שמקורם בפרויקטים קודמים.

## ההבדל הגדול נמצא מתחת לפני השטח: WebGPU

דפדפנים מציעים כבר שנים ממשקי ציור כמו Canvas 2D ו-WebGL. WebGPU הוא ממשק מודרני יותר, שמאפשר לאתרי אינטרנט להשתמש ב-GPU — המעבד הגרפי — הן לציור והן לחישובים מקביליים. במקום להעביר כל פעולת ציור דרך רצף ארוך של קריאות JavaScript, אפשר לארגן את הנתונים והפקודות כך שה-GPU יבצע חלק גדול מהעבודה במקביל.

הבעיה היא ש-WebGPU אינו ממשק פשוט למתחילים. השימוש בו דורש היכרות עם מושגים כמו adapters, devices, buffers, pipelines, shader modules ופורמטים של נתונים. q5 מנסה להסתיר את רוב המורכבות הזאת מאחורי פעולות מוכרות: היוצר קורא לפונקציות כמו circle, rect או line, והספרייה מתרגמת אותן לפקודות שהמנוע הגרפי יודע לבצע.

אבל ההפשטה הידידותית מסתירה מערכת לא קטנה. בקוד המקור של q5 אפשר למצוא צינורות רינדור (render pipelines), אחסון של נתוני צבע וטרנספורמציות ב-storage buffers, שימוש ב-shaders שנכתבו ב-WGSL והרכבת צורות באמצעות primitive topology מסוג triangle-strip. מאחורי פקודת ציור פשוטה פועלת, אם כן, שכבה שלמה שאחראית לניהול משאבי ה-GPU.

אחת הבחירות ההנדסיות המעניינות נוגעת לשימור התמונה בין פריימים. לפי תיעוד המקור של הפרויקט, אי אפשר לקרוא בחזרה באופן פשוט אל ה-CPU את הציור שכבר הוצג על canvas של WebGPU. כדי לשמור את התוצאה הקודמת, q5 משתמשת בשתי textures: אחת מכילה את הפריים הקודם, והשנייה משמשת לציור הפריים הבא. בכל מחזור התמונה מועתקת ביניהן. כך מגבלה של ממשק גרפי מסוים משפיעה ישירות על מבנה המנוע.

גם להצגת טקסט יש ב-q5 פתרון ייעודי. הספרייה משתמשת בטכניקת MSDF — ייצוג אותיות באמצעות שדות מרחק חתומים מרובי-ערוצים — שמאפשרת להציג טקסט חד בגדלים שונים. במילים אחרות, q5 אינה רק שכבה דקה שמתרגמת פקודות ציור לממשק קיים; היא כוללת החלטות מימוש שנועדו להתאים את העבודה לאופן שבו ה-GPU מצייר.

## מתחילים במשפט אחד, ומתקדמים משם

אחד היעדים של q5 הוא לקצר את הדרך מרגע פתיחת סביבת העבודה ועד לקבלת תוצאה ראשונה על המסך. באתר [q5js.org](https://q5js.org/) נמצאת סביבת למידה עם דוגמאות אינטראקטיביות שאפשר לערוך ישירות בדפדפן. כך אפשר להתנסות בספרייה גם בלי להתקין סביבת פיתוח.

דוגמה בסיסית בסגנון החדש של q5 נראית כך:

```js
await Canvas(400, 300);

background("#101820");
noStroke();
fill("#f2c14e");
circle(0, 0, 120);
```

הקריאה ל-Canvas יוצרת אזור ציור. אחריה אפשר לקבוע רקע, לבטל את קו המתאר, לבחור צבע ולצייר עיגול. בדוגמאות אינטראקטיביות אפשר להוסיף פונקציית draw שמריצה את הציור שוב ושוב, לקרוא קלט מהעכבר או מהמקלדת, ולשלב חישובים מתמטיים שמשנים את התוצאה לאורך זמן.

מי שכבר מכיר p5.js ימצא שמות פונקציות ומודל עבודה מוכרים למדי. q5 מצהירה גם על תאימות לתוספים פופולריים, ובהם p5.sound,‏ ml5.js ו-q5play. עם זאת, בפרויקט שמשלב כמה ספריות כדאי לבדוק את הגרסאות ואת הפונקציות הדרושות בפועל. הצהרת תאימות אינה מבטיחה שכל תוסף וכל תכונה יעבדו ללא התאמות.

אפשר להתקין את החבילה בפרויקט JavaScript באמצעות:

```bash
npm install q5
```

החבילה כוללת גם הצהרות TypeScript. בקובץ package.json מוגדרות נקודות כניסה נפרדות לדפדפן, ל-Deno ול-Node.js. במסלול של Node.js, הקובץ q5-server.js נעזר ב-skia-canvas וב-jsdom כדי לספק סביבת canvas ו-DOM מדומה. אלה תלויות של סביבת ההרצה הזאת, ולא חלק מהשימוש הרגיל בספרייה בדפדפן.

## לא רק JavaScript: גם Python

אחת התוספות הפחות שגרתיות של q5 היא האפשרות לכתוב sketches בשפת Python. הפרויקט כולל מודול Python ותיעוד ייעודי, וכן קובצי טיפוסים והצהרות שמאפשרים לעורכי קוד לזהות את הפונקציות הזמינות.

חשוב לדייק במשמעות של התמיכה הזאת: הדפדפן לא הפך לסביבת Python מקורית. לפי היסטוריית הגרסאות, המימוש נשען על Brython — מערכת שמאפשרת להריץ קוד Python בדפדפן באמצעות תרגומו ל-JavaScript. זהו גשר שימושי למי שלומד Python ורוצה ליצור תוצרים חזותיים, אבל הוא מוסיף שכבה טכנולוגית שצריך להביא בחשבון כשבודקים ביצועים, תאימות או שגיאות.

התמיכה הזאת מרחיבה את קהל המשתמשים האפשרי. מורים, תלמידים, אמנים ומתכנתים שמעדיפים את התחביר של Python יכולים להתנסות באותם רעיונות גרפיים. היא גם מלמדת משהו על הכיוון של q5: הפרויקט מבקש להקל על המעבר מרעיון לניסוי, ולא מסתפק בשיפור מהירות הציור.

## ומה לגבי ההבטחה לביצועים?

באתר q5 מוצגת השוואת ביצועים שמודדת כמה צורות אפשר לצייר בכל פריים, ברזולוציית 4K ובקצב של 60 פריימים לשנייה, על MacBook Air משנת 2025. בהשוואה מופיעה q5 במסלול WebGPU לצד p5.js במסלולי Canvas2D ו-WebGL.

זה נתון שכדאי להכיר, אבל צריך להבין מה הוא מודד — ומה לא. מדובר במדד מסוים, במחשב מסוים ובתרחיש בדיקה מסוים. הוא לא מוכיח שכל sketch יהיה מהיר פי מאה, או ש-q5 תהיה מהירה יותר בכל סוג של ציור, אנימציה או עיבוד תמונה. הביצועים מושפעים מסוג הפעולות, מכמות הנתונים שמועברת ל-GPU, מהרזולוציה, מהמכשיר ומהדפדפן. לכן נכון להתייחס למספרים שמציג האתר כתוצאות של בדיקה שערך הפרויקט, ולא כאל benchmark אוניברסלי.

גם בקוד המקור q5 אינה מסתירה את המחיר של הבחירה בביצועים. תיעוד מודול WebGPU מציין שהמטרה היא להשיג ביצועים, ולא לשחזר את כל היכולות של Canvas2D או SVG. למשל, אין תמיכה בכל סוגי דפוסי הקו ובכל סיומות הקו; מצולעים קעורים אינם ניתנים לציור כצורה מותאמת אחת ויש לפרק אותם למצולעים קמורים; והעלאת תמונות ל-GPU עלולה להיות איטית, משום שהתמונה צריכה לעבור המרה ל-texture. גם קריאה של ערכי פיקסלים, למשל באמצעות get על canvas, אינה זמינה במסלול WebGPU.

לא כל אחת מהמגבלות האלה היא בהכרח פגם. הן נובעות מבחירה להתמקד במקרים שבהם אפשר לצייר מספר גדול של צורות במהירות, גם אם פעולות שמוכרות ממנועים אחרים דורשות פתרון חלופי. מבחינת מפתח, המשמעות פשוטה: לפני שבוחרים ב-q5, צריך לבדוק אם היכולות שהיא מספקת מתאימות לסוג היצירה שמתכננים — ולא להסתמך רק על נתון ביצועים מרשים.

## התאימות לדפדפן היא חלק מהסיפור

WebGPU עדיין אינו זמין באופן אחיד בכל הדפדפנים והמכשירים. תיעוד MDN מסמן אותו כתכונה שזמינותה מוגבלת, ומציין שהוא דורש הקשר מאובטח — בדרך כלל אתר HTTPS. התמיכה תלויה גם במערכת ההפעלה, בדפדפן ובחומרה הגרפית.

q5 מנסה להתמודד עם המצב באמצעות מנגנון fallback — מעבר למסלול חלופי. אם אתחול WebGPU נכשל או שהדפדפן אינו תומך בו, הספרייה יכולה לעבור ל-Canvas2D. בקוד המקור אפשר לראות שהיא בודקת אם WebGPU זמין, מבקשת adapter ו-device, ואם המנוע הגרפי אינו יכול לפעול, יוצרת renderer חלופי. זהו מנגנון חשוב, אבל הוא לא מבטיח תוצאה זהה בשני המסלולים: ייתכנו הבדלים בביצועים וגם ביכולות.

לכן, לפני שמשלבים את q5 בפרויקט שמיועד לקהל רחב, כדאי לבדוק באילו דפדפנים ומכשירים משתמשים הקוראים, לוודא שמסלול ה-fallback תומך בפונקציות הנדרשות ולבחון את התוצאה גם בלי WebGPU. אם הפרויקט נשען על shader מותאם אישית או על תכונה ייחודית למנוע, ייתכן שמעבר ל-Canvas2D ידרוש התאמות נוספות.

## למי כדאי לנסות אותה?

q5 מתאימה במיוחד למי שרוצה ליצור אמנות גנרטיבית, הדמיות אינטראקטיביות, צעצועים חזותיים, ניסויים בצורות ובתנועה או פרויקטים חינוכיים שבהם חשוב להגיע במהירות לתוצאה. היא עשויה לעניין גם מפתחים שכבר מכירים p5.js ורוצים לבחון מסלול רינדור אחר, וכן מי שרוצה לראות כיצד ממשק פשוט יכול להסתיר מאחוריו מערכת WebGPU ממשית.

לעומת זאת, לא כדאי לבחור בה באופן אוטומטי לכל יישום גרפי. אם נדרשת תאימות רחבה במיוחד, אם הפרויקט משתמש בפונקציות מתקדמות של Canvas2D או אם הוא תלוי בקריאה תכופה של פיקסלים ובמניפולציות תמונה, צריך לבדוק היטב את הפערים. גם מי שמחפש מנוע משחקים מלא, מערכת תלת-ממד כללית או סביבת עיצוב מקצועית יגלה ש-q5 ממוקדת במשימה מצומצמת יותר.

## הרעיון שמאחורי q5

העניין ב-q5 אינו מסתכם במהירות הציור. הפרויקט מנסה להמשיך רעיון ותיק — להשתמש בתכנות כדי לחשוב, לשחק וליצור — בתוך עולם שבו החומרה והדפדפנים משתנים. הוא מאפשר למתחילים לכתוב פקודה כמו `circle(0, 0, 80)`, ובו בזמן מפעיל מאחורי הקלעים buffers,‏ shaders ו-pipelines של GPU.

כאן נמצא גם המתח המרכזי של הפרויקט. ככל שהמנוע מסתיר יותר פרטים, קל יותר להתחיל לעבוד איתו. אבל ככל שהוא מנצל יכולות חומרה מתקדמות יותר, כך חשוב להבין את מגבלותיו, את התאימות שלו ואת ההבדלים בין מסלולי הרינדור. q5 לא מעלימה את המורכבות; היא מנסה להרחיק אותה ממי שרק רוצה להתחיל לצייר, בלי למנוע ממי שמעוניין בכך להעמיק ולגלות איך המנוע פועל.

מי שרוצה לראות כיצד פקודת ציור פשוטה פוגשת את אחת משכבות הגרפיקה החדשות של הדפדפן יכול להתחיל בדוגמאות באתר q5, לעבור לקוד המקור ולבחון בעצמו אם היתרונות של WebGPU מצדיקים את הפשרות.

- [README של q5.js](https://github.com/q5js/q5.js/blob/main/README.md) — מטרות הפרויקט, דוגמאות, תוספים נתמכים והצהרת הרישוי.
- [תיעוד הלמידה של q5](https://q5js.org/learn/) — הפניות API ודוגמאות אינטראקטיביות.
- [עמוד הבית של q5](https://q5js.org/home/) — סביבת הניסוי, פורמט sketch חדש והשוואת הביצועים שהפרויקט מציג.
- [תיעוד ארכיטקטורת המקור](https://github.com/q5js/q5.js/blob/main/src/readme.md) — מודולי Canvas2D ו-WebGPU, מבני נתונים, מגבלות ופשרות מימוש.
- [קובץ package.json](https://github.com/q5js/q5.js/blob/main/package.json) — גרסת החבילה, נקודות כניסה, תלויות וסקריפטי build.
- [רישיון LGPL-3.0](https://github.com/q5js/q5.js/blob/main/LICENSE.md) — תנאי השימוש, השינוי וההפצה.
- [היסטוריית הגרסאות](https://github.com/q5js/q5.js/releases) — שינויים ותיקונים בגרסאות.
- [p5.js — מהי הספרייה](https://p5js.org/about/) — רקע על יצירה חישובית ועל הפרויקט שממנו q5 שואבת השראה.
- [MDN: WebGPU API](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API) — יכולות הממשק, דרישת HTTPS ומצב התמיכה בדפדפנים.
